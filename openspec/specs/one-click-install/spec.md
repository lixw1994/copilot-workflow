# one-click-install Specification

## Purpose

Install the engineering workflow (OpenSpec + ADR + skills + discipline hooks) and the optional Herdr squad enhancement into any project with one command: merge-based, idempotent, progressive — only the workflow enters the target project's version control.

## Requirements

### Requirement: One-command template installation

The system SHALL provide an `init.sh` script that, run once in the target project root, installs the engineering workflow (OpenSpec workspace, ADR directory, companion skills, discipline hooks) and the optional Herdr squad enhancement. Squad assets MUST install into the target project's `.herdr/` (sourced from the template repository's `squad/`), and `.herdr/` MUST be added to the target `.gitignore` — only the workflow enters version control; the squad is a machine-level environment.

#### Scenario: Install into a brand-new project

- **WHEN** the user runs `init.sh` in an empty git repository
- **THEN** the target gains `AGENTS.md` (with the marker block), `.herdr/` (squad protocol, roles, config, script, handoff directory), `scripts/pre-commit.sh`, `openspec/` (with both `spec-driven-with-adr` and `minimalist` schemas, default `spec-driven-with-adr`), `adr/`, `.agents/skills/`, `.git/hooks/pre-commit`, and the `.copilot-workflow.yaml` manifest; `.gitignore` contains a `.herdr/` entry; the script exits 0

#### Scenario: Remote one-liner execution

- **WHEN** the user executes via `curl -fsSL <url>/init.sh | bash` with no local template repository
- **THEN** the script clones the template repository into a temp directory as the install source and cleans it up afterwards

#### Scenario: AGENTS.md enables the squad conditionally

- **WHEN** after installation an agent reads `AGENTS.md` in an environment without Herdr (`HERDR_ENV` unset or `.herdr/AGENTS.md` absent)
- **THEN** the marker block directs it to work solo; the engineering workflow (OpenSpec + ADR + hooks) applies as usual and no squad collaboration requirements appear

### Requirement: Merge-based installation never destroys existing content

Installation MUST be merge-based: files already present in the target project are never overwritten or deleted.

#### Scenario: Target already has AGENTS.md

- **WHEN** the target project already has an `AGENTS.md` without this template's marker block
- **THEN** the script appends a section wrapped in `<!-- copilot-workflow:begin -->` and `<!-- copilot-workflow:end -->` at the end of the file, and content outside the block remains byte-for-byte identical

#### Scenario: Target already has a hook of the same name

- **WHEN** the target's `.git/hooks/pre-commit` exists and was not generated by this template
- **THEN** the script backs it up as `pre-commit.backup.<timestamp>` and the new hook chain-calls the backup first, preserving original behavior

### Requirement: Idempotent rerun equals upgrade

Repeated execution SHALL be safe: managed content is updated to the current template version and user content is untouched. Running the template repository against itself MUST be equally safe (assets whose source and target paths coincide are not replaced; only derived artifacts such as the `.herdr/` instance are generated).

#### Scenario: Rerun the installer

- **WHEN** the user runs `init.sh` again in a project that already has it installed
- **THEN** the marker block content and managed files are replaced with the new version, the version in `.copilot-workflow.yaml` updates, content outside the block, user-created files, `.herdr/squad.local.conf`, and `.herdr/handoff/` contents remain untouched, and the script exits 0

#### Scenario: Template repository self-install

- **WHEN** `./init.sh` runs in the template repository root
- **THEN** the `.herdr/` instance is generated or refreshed from `squad/` source, versioned source files in the repo are neither deleted nor rewritten, `git status` shows no changes beyond managed derived artifacts, and the exit code is 0

### Requirement: Selectable components

The user SHALL be able to select a component subset via `--with` (`squad`, `openspec`, `adr`, `skills`, `hooks`); the default is all.

#### Scenario: Install a subset of components

- **WHEN** the user runs `init.sh --with squad,adr`
- **THEN** only the `AGENTS.md` marker block, `.herdr/`, and `adr/` are installed; `openspec/`, `.agents/skills/`, and hooks are not created; the manifest records the actually installed component list

### Requirement: Language preference for OpenSpec artifacts

The script SHALL accept `--language <language>` controlling the language OpenSpec generates artifacts in, defaulting to English.

#### Scenario: Default install

- **WHEN** the user runs `init.sh` without `--language`
- **THEN** the OpenSpec workspace is initialized with English as the artifact language

#### Scenario: Configure Chinese

- **WHEN** the user runs `init.sh --language "Simplified Chinese"`
- **THEN** the OpenSpec workspace is initialized with Simplified Chinese as the artifact language

### Requirement: Dependency checks with progressive degradation

The script MUST check dependencies before acting: a missing git fails fast with install guidance; missing optional dependencies such as the openspec CLI skip the affected component, record a precise remediation command, and are summarized at the end without interrupting other components. Missing squad runtime dependencies (jq, herdr) only produce a notice and never block.

#### Scenario: Missing openspec CLI

- **WHEN** the environment has no `openspec` command and the user did not exclude the `openspec` component
- **THEN** the script prints install guidance (`npm install -g @fission-ai/openspec@latest`) and continues with the remaining components, exits 0, and the manifest does not record the `openspec` component

#### Scenario: Missing squad runtime dependencies

- **WHEN** the environment lacks the `jq` or `herdr` command
- **THEN** installation completes normally; the closing output notes the missing runtime dependencies with install instructions and states that the workflow itself is unaffected

### Requirement: Cold-start guidance for existing projects

After installation the script SHALL print next-step guidance; for projects with existing code, the guidance MUST include onboarding hints for deriving initial specs and backfilling ADRs.

#### Scenario: Installation completes in an existing project

- **WHEN** the install target contains pre-existing code files beyond `.git`
- **THEN** the printed guidance includes: have the agent derive initial specs from the existing code and backfill the most important established architecture decisions as ADRs (marked as retroactive)
